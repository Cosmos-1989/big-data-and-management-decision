## 组织顺序

1. 用同一批订单的两个准时率解释统计对象与分母的重要性。
2. 由数据用途说明质量要求，再说明记录如何产生、质量维度、业务核验和数据剖析。
3. 在讨论统计误差以前，先解释可执行规则、违规行集合及 SQL 如何找回具体记录。
4. 按记录缺失、缺失结果的界限、测量误差、比率误差的次序分析统计后果，最后讨论比较方案所需的误差范围。
5. 从违规记录的影响范围进入统计报警、误报与漏报、发布的预期损失及修复预算分配。
6. 定义治理职责、数据契约、血缘及变更管理，再讨论真实企业的目录与监测实践、文档知识库质量。
7. 用完整的背景、输入、规则、输出和回查办法组织订单实验，保留原程序并解释其实际行为。

把两张反复出现的技术清单折叠为可展开参考表，原表格与定位 ID 均保留。数据剖析的定义移到本小节开头；血缘图移到血缘说明之后。企业平台名称保留在原理已经解释以后的应用部分，真实机构材料与本课假设算例分开表述。

## 概念与推理修复

- 对订单准时率说明示性函数、非空分母、实际日期和承诺日期的含义；用 72/80 与 72/100 对比已交付口径与到期承诺口径。
- 从首次出现处解释主数据、KPI、SQL、枚举、数据剖析、元数据、数据契约、数据血缘、智能体、语言模型与 RAG；英文测试名称附中文含义。
- 区分规则符合与记录准确，说明负数量和空日期需要由表的业务范围及订单状态解释。
- 说明缺失选择偏差恒等式涉及的总体、记录指示变量、样本均值的极限对象及有限期望条件。
- 明确本节 MCAR/MAR/MNAR 的模型范围为只有结果可能缺失、协变量完整记录。补上条件概率表达、MAR 的正记录概率条件、总体分组加权公式，以及组别变化会使直接平均偏移的可复算例子。
- 将缺失结果的识别区间与抽样置信区间分开；说明上下界来自已知取值限制，20 天上限需经业务核实。
- 经典衰减偏差保留原独立、均值和不相关条件，补有限方差及真实负载正方差；先定义观测负载并给出原斜率，再展开协方差和方差的推导。β解释为真实解释变量的总体线性拟合斜率，避免在只有不相关条件时误说成条件均值或因果效应。
- 比率误差解释分子、分母误差及分母为正的条件，说明保守界使用三角不等式和分母下界。补充 900 件良品、100 件不良品漏录的含义。
- 涉及重复事实的 O 与 tilde O 以记录多重集理解，保留同一业务记录的出现次数，与前面的记录序列及重复计数分析一致。
- 解释确定性规则和依据历史分布的统计报警；定义误报、漏报，区分显著性水平与收到告警后的错误概率。增加 10000 个批次的示例，告警后错误概率为 90/585。
- 发布选择明确比较同一时段的损失，并说明相等时两种选择在简化模型中等价，已有强制发布约束按其要求执行。
- 修复预算模型补概率初值不超过 1、有限资产及非负预算条件；预算为 0 时全部零投入，预算为正时才说明预算用完和正投入对象的共同边际收益。
- 良率比较明确只根据各自误差界所得的结论；区分绝对误差界、标准误和质量规则失败率。
- 医疗案例不把假设的预约等待天数例子冒充来源公开事实。Monte Carlo明确为数据可观测性厂商，避免与同名仿真方法混淆。智能体取得材料以后只据来源说明状态和记录中的延期环节，成因判断仍需经营证据。

## 对实际程序的核对

读取并只读运行了当前配套 `quality/checks.py` 与 `cases/week04_data_quality.py`，未修改程序。

- 第二段 SQL 的 `IS NOT NULL` 已排除空客户编号，查询只报告非空而未匹配的编号；空编号由单独的非空规则报告。
- 页面运行入口实际为 `render_quality_report_markdown(dirty=True)`，不是 `main()`；正文据此解释加载、调用和显示。
- `check_unique` 对一个重复键只产生一条问题记录，`row_id` 为该业务键。`issue_count`、严重级别及质量维度统计均按问题记录计数。
- 受影响的原始物理行必须回查全部匹配记录，再用独立源行标识或文件行号计数；业务键去重数、问题条数和物理行数分别解释。
- 本课问题样例实际输出为 9 行、10 条问题记录，严重级别为 error 8 条、warning 2 条；维度为完整性 2 条、一致性 3 条、唯一性 1 条、有效性 4 条。以上数值已写入实验的输出核对说明。
