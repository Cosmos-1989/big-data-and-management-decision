## 重要修复与补充

1. 明确 SQL 未指定去重时保留重复次数，经典关系代数投影则会去重。两张不同的100元订单合计200元，不可仅按金额去重。
2. 连接行数不变依赖右键唯一及左侧外键完整匹配；行数恰好相同仍可能同时发生遗漏与重复，因此按事实主键核对覆盖和匹配次数。
3. 修正原命题用“通常”诊断行数变化的含混写法，命题仅陈述精确充分条件；后段说明总行数核查的局限。
4. 指标定义中将分组符号解释为“由指定维度确定的分组集合”，与后文按组求和及组数取平均一致。补全所有 KPI 公式的数量、价格、成本、日期、订单数和指示函数含义。
5. 比率明确要求互斥事实组、相同口径及正分母，增加分母权重表示；分母不同也可能偶然同值，不再暗示只有等分母才能相同。
6. 以两组2张/8张订单说明均值需要保留总和与数量，补结合律与无序事实合并次序的意义。
7. 将 NULL 的业务状态与三值逻辑放在 OTD 计算之前。说明计行数与计非空字段的区别、求和忽略 NULL 可能只给出已知部分的合计。
8. 用同一批四张订单说明到期承诺50%与已交付口径66.7%的不同分母，固定观察截止时点及承诺版本；说明迟交后不能改变原先逾期事实。
9. 明确条件聚合 SQL 的 `WHERE actual_date IS NOT NULL` 同时限定收入与毛利，`AVG(delay_days)` 的样本为全部已交付订单（准时为0天）。没有候选订单的地区不会自动产生结果行，`NULLIF`不补分组。
10. 安全除法只处理零或空分母，不被表述为能够修复口径不一致。
11. 制造公式前解释工站、产品族、Yield、Cycle Time、OEE、WIP及其单位和范围，OEE 分解明确正分母条件，WIP 积分明确观察期长度为正。补不同产品节拍的质量权重数值例。长期未完成批次以年龄单列，避免只观察完成批次的选择问题。
12. 窗口 SQL 逐项解释分区、排序、ROWS 和序号。三条记录与七个日历日分开；先过滤3月再计算窗口会丢失2月历史，需要先计算足够历史再筛展示日期。
13. 订单实验说明经营问题、输入文件及各表粒度、输出表、计算次序与报告要求。Python `summarize_by`对全输入计收入、仅已交付计交付表现；与前文已交付样本 SQL 对照时须限制同一输入。
14. 制造程序原有“输入行均值 WIP”“按记录数窗口”“件数质量率分解 OEE”“零分母返回0”的具体约定保留解释，不将它们误称为所有目标口径的普遍实现。
15. 自然语言问数先定义请求与验证方法，再谈平台；解释模型、语义服务、产品名称、容器、向量、上下文长度与并发。可回答任务的合格率与越权拒绝测试分别统计。
