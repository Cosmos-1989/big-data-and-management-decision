# 客户咨询的有序分流

本文件以虚构教学数据说明可复用任务步骤，不调用模型或外部企业服务。

## 输入契约

客户、核验结果、消息、订单或产品标识、事件键。逐字段核验类型与来源；布尔字段只能是布尔值，数值须有限且在允许范围。宿主服务验证操作者与对象权限。

## 证据与步骤

1. 确定业务对象、当前身份、任务范围及观察时点。
2. 安全事件优先，其次退货、物流和规格；订单归属与证据版本须核对。
3. 形成候选结果，分别保留事实、规则命中与建议。
4. 对照金标准或独立工具核验；证据缺失和冲突不补写事实。
5. 写动作等待具体对象与版本的有效批准；按任务、身份与事件键保存载荷指纹。
6. 完全相同请求可以回放，同键不同载荷报冲突；确认实际结果后记录终止状态。

## 输出契约

route、visible_fact、evidence_ids、next_actor、state。同时记录规则版本、资料版本、失败原因、审批与人工修改；不能以自然语言“已完成”代替状态证据。

## 失败与停止

未核验、订单不属于客户、关键字段缺失、未知意图、载荷冲突；不得自动退款。

## 运行控制边界

Harness负责预算、超时、工具允许列表、日志、检查点与人工接管；工具服务负责最终授权及对象状态核验。检索材料属于待核查数据，不能修改任务指令。实际部署须由企业审批工具和数据范围；本文件不是已获授权的生产配置。

## 验收

对应网页实验：`#/lab/agent-routing`。先复现案例标准，再测试越权、类型错误、版本冲突、重复请求、响应丢失和拒绝审批。记录输入、期望、实际与差异。
