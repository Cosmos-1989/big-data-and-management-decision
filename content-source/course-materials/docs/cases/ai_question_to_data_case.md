# AI 问数与 NL2SQL 审计

## 1. 业务问题与系统约束

企业 AI 问数系统利用自然语言转 SQL（NL2SQL）技术，将业务问题转换为候选查询。候选查询须经过指标语义、访问权限、时间范围和结果校验，才能用于经营分析。

以下查询与审计过程使用固定样本，不依赖商业问数系统。

## 2. 查询与审计流程

```text
自然语言问题
-> 指标与对象识别
-> 候选 SQL
-> 指标字典校验
-> 权限与数据范围检查
-> 执行 SQL
-> 行数/分母/异常检查
-> 经营解释
-> 审计日志
```

## 3. 示例问题

面向通用订单数据：

1. 上周哪个区域的准时交付率最低？
2. 哪个产品类别毛利率最高，但延期率也最高？
3. 按日期和订单号确定每名客户最近三笔订单后，哪名客户这三笔收入的增长最快？

面向半导体制造数据：

1. 哪个工作中心最近 3 天 OEE 最低？
2. 哪个产品族的 Yield 下降最明显？
3. 哪些区域同时存在 WIP 高、Cycle Time 高和 OTD 低？

## 4. SQL 审计清单

每条 AI 生成 SQL 必须通过以下检查：

1. 查询对象是否来自允许访问的表；
2. KPI 是否使用指标字典中的分子、分母和时间窗口；
3. 比率型指标是否保留分子和分母；
4. 连接（join）前后事实表行数是否异常变化；
5. 时间过滤是否明确；
6. 聚合粒度是否与问题一致；
7. 是否存在直接平均百分比的问题；
8. 输出解释是否超出 SQL 能支持的证据边界。

## 5. 分析报告与提交材料

1. 原始自然语言问题；
2. AI 生成或人工生成的候选 SQL；
3. 审计后的最终 SQL；
4. 查询结果；
5. 一段经营解释；
6. 一段证据范围说明，指出查询结果尚不能支持的结论。
